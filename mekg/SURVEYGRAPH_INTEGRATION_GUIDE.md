# SurveyGraph 项目集成指南

## 项目概述

**SurveyGraph** 是基于 SurveyX 项目的自动综述生成科研系统，核心创新在于引入 **MEKG (Methods-Entity Knowledge Graph，方法实体知识图谱)** 来替代传统的 RAG 向量召回方案，实现更有逻辑性的综述生成和评估。

---

## 一、系统架构

### 1.1 整体流程

```
用户输入研究主题 (Topic)
        ↓
┌─────────────────────────────────────┐
│     Phase 1: MEKG 知识图谱构建       │
│  - 论文采集 (OpenAlex API)           │
│  - 语义实体抽取 (7种实体类型)         │
│  - 关系发现 (21种关系类型)            │
│  - 图谱分析 (社区发现、中心性计算)    │
└─────────────────────────────────────┘
        ↓
┌─────────────────────────────────────┐
│     Phase 2: 综述大纲生成            │
│  - 基于图谱结构生成大纲               │
│  - 社区驱动的章节划分                 │
│  - 演进路径驱动的时间线               │
└─────────────────────────────────────┘
        ↓
┌─────────────────────────────────────┐
│     Phase 3: 综述内容撰写            │
│  - 图谱驱动的论文挂载                 │
│  - 基于原子事实的内容生成             │
│  - 多智能体协作写作                   │
└─────────────────────────────────────┘
        ↓
┌─────────────────────────────────────┐
│     Phase 4: 综述质量评估            │
│  - 基于图谱的覆盖率评估               │
│  - 结构一致性评估                     │
│  - 引用准确性评估                     │
└─────────────────────────────────────┘
        ↓
输出: 高质量学术综述论文 (PDF/LaTeX)
```

### 1.2 与传统 SurveyX 的区别

| 维度 | SurveyX (传统RAG) | SurveyGraph (MEKG) |
|------|-------------------|---------------------|
| 论文召回 | 向量相似度检索 | 图谱结构化检索 |
| 大纲生成 | LLM直接生成 | 基于社区和演进路径 |
| 论文组织 | 扁平化列表 | 层次化知识图谱 |
| 关系理解 | 无 | 21种语义关系 |
| 可解释性 | 低 | 高 (有明确证据链) |
| 评估能力 | 有限 | 基于图谱的多维评估 |

## 二、MEKG 知识图谱核心概念

### 2.1 什么是 MEKG

MEKG (Methods-Entity Knowledge Graph) 是一个以**方法实体**为核心的学术知识图谱。与传统的引用网络不同，MEKG 不仅记录论文之间的引用关系，还深入分析论文的语义内容，提取方法、任务、数据集等实体，并发现它们之间的语义关系。

### 2.2 语义实体类型 (7种)

MEKG 从论文中抽取以下7种语义实体：

1. **PROBLEM** - 研究问题：论文试图解决的核心问题
2. **METHOD** - 方法/技术：论文提出或使用的方法
3. **MODEL** - 模型/架构：具体的模型名称或架构
4. **TASK** - 任务：论文针对的具体任务
5. **DATASET** - 数据集：使用的数据集
6. **METRIC** - 评估指标：使用的评估指标
7. **INNOVATION** - 创新点：论文的主要创新贡献

### 2.3 关系类型 (21种)

MEKG 支持5大类共21种关系类型：

**结构关系 (基于引用网络)**
- cites / cited_by - 引用关系
- co_cited - 共被引 (两篇论文被同一篇论文引用)
- bibliographic_coupling - 文献耦合 (两篇论文引用相同的论文)

**语义关系 (基于内容分析)**
- extends - 扩展 (B扩展了A的方法)
- improves - 改进 (B改进了A的方法)
- compares - 比较 (B与A进行了对比实验)
- applies - 应用 (B将A的方法应用到新领域)
- contradicts - 矛盾 (B的结论与A矛盾)
- supports - 支持 (B的结论支持A)

**概念关系 (基于共享实体)**
- shares_method - 共享方法
- shares_task - 共享任务
- shares_dataset - 共享数据集
- shares_model - 共享模型
- shares_problem - 共享问题

**时间关系**
- precedes / follows - 时间先后
- contemporary - 同时期

**作者关系**
- same_author - 同作者
- same_venue - 同会议/期刊
- same_institution - 同机构

### 2.4 关系发现策略

MEKG 采用四层关系发现策略：

**第一层：引用关系 (100%可靠)**
- 直接从论文元数据获取
- 包括直接引用、共被引、文献耦合

**第二层：引用上下文分析 (规则+LLM)**
- 分析引用句的上下文
- 使用规则匹配常见模式
- 复杂情况使用LLM判断

**第三层：共享实体分析 (语义匹配)**
- 比较两篇论文的语义实体
- 发现共享方法、任务、数据集等关系
- 这是"方法论拆解"的核心实现

**第四层：LLM深度分析 (复杂关系)**
- 对于无法通过规则判断的关系
- 使用LLM分析论文摘要和方法描述
- 判断是否存在扩展、改进等语义关系

## 三、MEKG 模块结构

### 3.1 目录组织

```
mekg/
├── src/                   # 核心源代码
│   ├── core/              # 核心数据结构
│   ├── extraction/        # 实体和关系抽取
│   ├── processing/        # 数据处理
│   ├── storage/           # 存储层
│   ├── analysis/          # 图谱分析
│   ├── automation/        # 自动化构建
│   └── visualization/     # 可视化
├── scripts/               # 运行脚本
├── webapp/                # Web控制台
├── docs/                  # 文档
└── data/                  # 数据目录
```

### 3.2 核心模块说明

**core 模块**
- MEKGGraph：知识图谱主类，管理节点和边
- MEKGNode：论文节点，包含元数据和语义实体
- MEKGEdge：关系边，包含关系类型和置信度
- MEKGAnalyzer：图谱分析器，提供中心性计算、社区发现等功能

**extraction 模块**
- SemanticEntityExtractor：从论文中抽取7种语义实体
- CitationContextAnalyzer：分析引用上下文，识别8种引用意图
- EnhancedRelationDiscoverer：发现21种关系类型
- IntelligentCandidateGenerator：智能生成候选论文对，减少LLM调用

**processing 模块**
- PaperPoolCollector：从OpenAlex采集论文
- PDFProcessor：下载和解析PDF
- EntityCleaner：清洗和验证抽取的实体
- EntityDisambiguator：实体消歧，合并同义实体

**storage 模块**
- SemanticEntityDB：SQLite存储，支持持久化
- MemgraphGraphDB：Memgraph图数据库（可选）
- KuzuGraphDB：Kuzu嵌入式图数据库（可选）

**analysis 模块**
- CommunityLabeler：社区发现和命名
- CorePaperDiscoverer：识别核心论文
- IGraphAdapter：高性能图算法适配器
- EvaluationMetrics：评估指标计算

**automation 模块**
- IncrementalBuilder：增量构建器
- PipelineOrchestrator：流水线编排器
- CrawlerManager：爬虫管理器

## 四、集成到 SurveyGraph 的步骤

### 4.1 Phase 1: 基础集成

**目标**：将 MEKG 模块作为独立包集成到项目中

**步骤**：
1. 将 `mekg/` 文件夹复制到 SurveyGraph 项目根目录
2. 在 `requirements.txt` 中添加 MEKG 依赖
3. 配置数据库路径和 LLM API

**依赖项**：
- networkx：图数据结构
- python-louvain：社区发现
- httpx：异步HTTP请求
- loguru：日志
- igraph（可选）：高性能图算法
- kuzu（可选）：嵌入式图数据库

### 4.2 Phase 2: 论文采集集成

**目标**：使用 MEKG 的论文采集替代原有方案

**关键组件**：
- PaperPoolCollector：调用 OpenAlex API
- 支持多关键词搜索和雪球采样
- 自动去重和排序

**采集策略**：
1. 智能关键词拆分：LLM判断是否需要拆分主题
2. 多关键词并行搜索：每个关键词分配配额
3. 雪球采样扩展：基于高引论文的引用网络扩展
4. 综述优先策略：优先采集相关综述论文

### 4.3 Phase 3: 图谱构建集成

**目标**：构建 MEKG 知识图谱

**流程**：
1. 论文入库：将采集的论文存入数据库
2. 语义实体抽取：使用 LLM 抽取7种实体
3. 实体清洗和消歧：规则验证 + 聚类合并
4. 关系发现：四层策略发现21种关系
5. 图谱分析：计算中心性、发现社区

**优化策略**：
- 智能候选对生成：减少98%的LLM调用
- 基于属性对比：不使用全文，降低80%成本
- 并发控制：10-20并发，避免API限流

### 4.4 Phase 4: 大纲生成集成

**目标**：基于 MEKG 生成综述大纲

**方法**：
1. 从图谱提取结构化信息：社区、演进路径、核心论文
2. 社区驱动章节划分：每个社区对应一个主题章节
3. 演进路径驱动时间线：展示方法的发展脉络
4. LLM语义优化：生成学术化的章节标题和描述

**与传统方法的区别**：
- 传统：LLM直接生成大纲，缺乏结构支撑
- MEKG：基于图谱结构生成，有客观依据

### 4.5 Phase 5: 内容撰写集成

**目标**：基于 MEKG 撰写综述内容

**方法**：
1. 图谱驱动论文挂载：为每个章节匹配相关论文
2. 基于原子事实写作：使用论文的原子事实而非全文
3. 关系驱动叙事：利用论文间关系组织叙述逻辑

**挂载策略**：
- 基于社区归属：同社区论文挂载到同章节
- 基于关键词匹配：章节关键词与论文实体匹配
- 基于关系链：沿着关系链扩展相关论文

### 4.6 Phase 6: 质量评估集成

**目标**：基于 MEKG 评估综述质量

**评估指标**：
1. **WCR (Weighted Centrality Recall)**：加权中心性召回率
   - 评估综述是否覆盖了领域内的核心论文
   
2. **CC (Community Coverage)**：社区覆盖率
   - 评估综述是否覆盖了所有主要研究方向
   
3. **SC (Structural Coherence)**：结构一致性
   - 评估综述结构是否与知识图谱结构一致

## 五、技术要点

### 5.1 LLM 调用优化

**问题**：大规模论文处理需要大量 LLM 调用，成本高昂

**解决方案**：
1. 智能候选对生成：只对高可能性的论文对调用 LLM
2. 基于属性对比：使用结构化属性而非全文
3. 分层处理：规则能解决的不用 LLM
4. 模型选择：使用 DeepSeek 等低成本模型

### 5.2 图谱存储

**Memgraph**：
- 优点：原生图数据库，查询性能好
- 适用：需要复杂图查询的场景

### 5.3 并发控制

**原则**：平衡速度和稳定性

**建议配置**：
- PDF下载：20并发
- 属性提取：20并发
- 关系发现：20并发

### 5.4 增量更新

**支持场景**：
- 新论文入库：只处理新论文
- 关系补充：只发现涉及新论文的关系
- 社区更新：增量更新社区划分

## 六、快速开始

### 6.1 最小可用配置

1. 复制 `mekg/` 到项目
2. 安装依赖：`pip install networkx python-louvain httpx loguru`
3. 配置 LLM API（支持 OpenAI 兼容接口）
4. 运行构建脚本

### 6.2 推荐配置

1. 安装 igraph 提升图算法性能
2. 使用 Kuzu 作为图存储
3. 配置 DeepSeek API 降低成本
4. 启用 Web 控制台监控进度

---

## 七、注意事项

1. **API 限流**：OpenAlex 和 LLM API 都有速率限制，需要合理控制并发
2. **存储空间**：大规模图谱需要较大存储空间
3. **处理时间**：1000篇论文完整处理约需2-4小时
4. **成本控制**：合理使用 LLM，避免不必要的调用
